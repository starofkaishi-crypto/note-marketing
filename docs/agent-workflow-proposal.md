# イラスト発信 × note記事制作 マルチエージェント・ワークフロー提案

イラストのマインドセット/テクニック論をnoteで発信し、有料noteの販売にもつなげるための、
役割別エージェントによる記事制作パイプラインの構想。

## 全体像

```
[ネタストック帳]
      │
      ▼
① 企画・リサーチ ──▶ ② 構成 ──▶ ③ 執筆 ──▶ ④ 品質チェック ──▶ ⑤ 入稿・公開・告知
      ▲                                   │(基準未達なら③へ差し戻し)
      └────────── ⑥ 振り返り(公開後の数値を次の企画へ還元)──────────┘
```

各工程を専任エージェントに分け、自分(ディレクター)は工程間の**承認ゲート**と
**経験談・作例の注入**だけに集中する。書く作業ではなく「判断」に時間を使うのが狙い。

---

## 各エージェントの役割

### ① 企画・リサーチエージェント
- **やること**: ネタ出し、トレンド調査(X・note人気記事・Pixivランキング等)、
  競合の有料note分析(価格帯・目次構成・無料公開範囲)、検索キーワード/ハッシュタグ調査
- **成果物**: 「企画ブリーフ」1枚
  - テーマ / 想定読者(例: 絵を描き始めて1〜2年で伸び悩んでいる人)
  - この記事ならではの切り口(自分の経験のどこを使うか)
  - 無料記事か有料noteか、有料なら想定価格
  - 参考にした記事・データのリスト

### ② 構成エージェント
- **やること**: ブリーフをもとに記事の設計図を作る
  - タイトル案3本(note検索とタイムラインでの引きを意識)
  - リード文の方針(読者の悩みを最初の3行で言い当てる)
  - 見出しと各節の要点、CTA(フォロー/スキ/有料誘導)の配置
- **有料noteの場合**: 無料部分と有料部分の線引きを設計する。
  「無料部分だけで1本の記事として価値がある + 続きが読みたくなる」が原則。

### ③ 執筆エージェント
- **やること**: 構成に沿って本文を書く。文体ガイド(トンマナ定義)に従う
- **重要な設計**: 経験談・作例・失敗談の箇所は `【体験談: ○○について2〜3行】` の
  プレースホルダで残す。**ここを自分の言葉で埋めるのが人間の最重要作業**。
  読者が課金するのは情報ではなく「この人の実体験と視点」なので、ここだけは外注しない。

### ④ 品質チェックエージェント
- **やること**: チェックリスト方式で機械的に審査し、スコアが基準未満なら③へ差し戻し
  - 誤字脱字・日本語の不自然さ
  - タイトルは検索キーワードを含み、かつ煽りすぎていないか
  - リード3行で「誰の・どんな悩みに・何を提供するか」が伝わるか
  - 見出しだけ読んで話の流れがわかるか
  - 技法・ツールに関する記述の事実確認
  - 有料noteの場合: 価格に対して具体性(手順・作例・演習)が見合っているか
- **成果物**: 指摘一覧 + 合否判定。執筆エージェントとは別人格にすることで
  「書いた本人が見直す」より確実に粗を拾える

### ⑤ 遂行(入稿・公開・告知)エージェント
- **やること**:
  - note入稿用の整形(見出しレベル、目次、画像挿入位置の指示、アイキャッチの指示書)
  - ハッシュタグ選定、公開日時の提案(ターゲット読者が読む時間帯)
  - X(Twitter)告知文の生成(公開直後用・翌日リマインド用の2本)
- **有料noteの場合**: 発売前の予告投稿、無料部分の切り出し告知も生成

### ⑥ 振り返りエージェント(任意・慣れてから)
- **やること**: 公開後1週間のビュー・スキ・購入数を記録し、
  「どのテーマ・タイトル型・価格帯が反応が良いか」を蓄積して①のリサーチに還元

---

## 運用ルール

1. **承認ゲート方式**: ①→②、②→③、④→⑤ の各段階で自分が成果物を確認して承認。
   途中で方向修正するほうが、完成後に書き直すよりはるかに安い。
2. **共通資産をリポジトリで管理**(エージェント全員が参照する):
   - `persona.md` — 想定読者の定義
   - `style-guide.md` — 文体・一人称・NG表現などのトンマナ
   - `checklist.md` — 品質チェック基準
   - `templates/` — 記事タイプ別テンプレート
   - `stock.md` — ネタストック帳(①が随時追記)
3. **週次バッチ運用**: リサーチは週1回まとめて行い、企画ブリーフを3〜5本ストック。
   平日は②〜⑤のパイプラインを1本ずつ流す。毎回ゼロからネタを探さない。

## 記事タイプ別テンプレート(案)

| タイプ | 型 | 主な用途 |
|---|---|---|
| マインドセット系 | ストーリー型(失敗→気づき→変化→読者への問いかけ) | 無料。共感でフォロワーを増やす |
| テクニック系 | チュートリアル型(before/after→手順→つまずきポイント) | 無料〜低額。検索流入と実力の証明 |
| 有料note | 体系化型(全体像→章立てされた手順→演習→特典) | 販売。無料記事で信頼を貯めてから |

## 販売戦略の基本線

- **無料のマインドセット記事で共感と信頼を貯め、有料のテクニック体系で回収する**二層構造
- 有料noteは「単発Tips の寄せ集め」ではなく「1つの課題を最後まで解決する教材」として設計
- 価格は競合調査(①の仕事)に基づき決定。最初は低め+購入者の声を集めて改訂・値上げ
- 返金設定ONと部分無料公開で購入ハードルを下げる

## 実装の選択肢(次のステップ)

この構想は Claude Code のサブエージェント機能でそのまま実装できる。
`.claude/agents/` に各エージェントの定義ファイルを置く形。例:

```markdown
---
name: research-agent
description: note記事の企画・リサーチ担当。テーマ候補から企画ブリーフを作成する
tools: WebSearch, WebFetch, Read, Write
---
あなたはイラスト系note記事の企画リサーチャー。persona.md と stock.md を読み、
指定テーマについて競合記事・トレンドを調査し、企画ブリーフを docs/briefs/ に出力する。
...
```

同様に writer / qa / publisher のエージェント定義と、上記の共通資産ファイル群を
このリポジトリに整備すれば、「/記事作成 ○○のテーマで」の一声でパイプラインが回る。
